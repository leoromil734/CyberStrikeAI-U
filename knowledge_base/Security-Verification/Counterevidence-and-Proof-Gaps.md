# 反证、安全控制时序与证明缺口

## 适用与触发

用于扫描候选、源码危险汇、认证授权差分的否定与收尾。
关注具体路径上的控制，不以库名、扫描空结果或环境无法启动判安全。
本方法深化现有验证流程，不创建新的机器状态或降低 confirmed 门槛。

## 前提与身份

- 固定目标、部署版本、构建、配置、入口、方法和当前轮次。
- 说明匿名、低权、其他租户或已失陷会话的起始权限。
- 标记输入是否真实可控，是否到达已部署的处理路径。
- 只有静态代码时，结论标静态分析；不得替代目标侧动态证据。

## 安全控制的可核查描述

完整描述应包含：某控制在某位置、对哪个值、如何限制、在什么效果之前执行。
还需说明所有当前攻击者可达的相关路径是否经过该控制。
路径集合是已调查范围，不是假定整个应用已穷尽。
检查返回值、错误分支、默认值、配置覆盖和失败开放行为。
认证先执行不代表对象授权、租户授权和字段授权也执行。
HTML 转义不证明 JavaScript 上下文安全；SQL 值参数化不证明动态标识符安全。
路径拼接不证明最终文件被限制在目录内。

## 基线与单变量对照

1. 正常授权输入应到达真实 handler 并得到预期结果。
2. 改变一个身份、对象或表示，观察具体拒绝原因和受保护状态。
3. 检查校验之后是否发生解码、重定向、内部调用、重试或后台处理。
4. 对共享 helper 的兄弟调用点分别建立适用性；安全兄弟路径不能证明全部安全。
5. 若对照被缓存、代理错误页或认证挑战拦截，保留缺口，不能归因于应用控制。
6. 允许时在受控副本使用安全反例证明控制被移除后测试确实会失败。

## 原始证据与归因

- 请求、响应、身份引用、时间、源码位置与实际执行版本相互对应。
- 指明被控制的值与最终消费值，而非只记录日志中的显示值。
- 阴性结论包括正常基线成功、攻击对照失败、命名控制及其时序证据。
- 静态不可达结论只适用于已分析构建与配置，不继承到其他部署。
- 完整保存事实引用；公开报告脱敏不能删除证明关系。

## 反证与常见误判

- 403 可能来自边缘层，不独立证明对象授权成立。
- 找不到调用方、缺第二身份、构建失败都不是安全证明。
- 未触发效果只否定本次输入和条件，不否定整个风险类别。
- 管理员正常操作、持有已失陷身份后读取自身数据，不是新增权限。
- operator 可以配置安全选项，不等于当前配置已生效。
- 内网或需登录可以限制利用条件，不能一概删除已证明风险。

## 终态与证明缺口

confirmed：目标侧可复现且相对起始状态获得新增能力，提交完整 POC 与 validation。
negated：限定入口、身份、方法、参数和版本，写明本次反证。
tentative：仍有合理假设，缺少输入可控性、路径或效果证据。
blocked：缺少必要身份、范围、网络、工具或时间；列替代路径与恢复条件。
proof gap（证明缺口）是解释字段，映射到 tentative/blocked，不发明账本枚举。
策略排除应写明本项目排除项，不能标成已验证安全。

## 停止、恢复与修复

同一入口、身份、方法、参数三次无新增证据，只关闭该组合并换路。
出现新增入口、身份、版本或控制失效证据时重新映射，保留旧历史。
缺前提只阻断对应单元；不因单个困难环境耗尽其他可执行候选预算。
优先在共享安全边界修复，保持不同入口一致、失败关闭并先于危险效果执行。
本项目 CORS、缺安全头、无影响配置弱项等低价值排除继续生效。
