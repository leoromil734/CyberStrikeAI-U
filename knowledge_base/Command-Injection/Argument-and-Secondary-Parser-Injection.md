# 无 Shell 参数注入与二次解析边界

## 适用与触发

应用把用户字段交给子进程、命令行客户端、配置解析器或响应文件时使用。
数组形式 subprocess 避免 Shell 分词，但目标程序仍可能解释选项和子语言。
本方法区别 shell injection、argument injection 与配置/表达式二次解析。

## 前提与运行环境

记录执行 API、平台、运行时、目标二进制/版本、路径、cwd、环境和身份。
记录输入是否可控、是否能到达实际进程，以及程序继承的真实权限。
仅批准的本地受控副本或授权目标允许验证，不启动陌生软件/安装依赖。
使用无敏感数据、无破坏性命令和可恢复对象，不建立持久化。

## 三个边界

POSIX execve 的数组元素保留边界：元素内部空格不自动产生额外参数。
字符串/Shell 形式先发生 Shell 解析；需单独分析引号和元字符。
Windows 常把数组序列化为字符串，由子进程运行时或应用重新解析。
Windows 不同 CRT、应用、自定义 parser 的规则可能不同，不泛化为通用绕过。
即使只有一个 argv 元素，目标也可能解释 URL、配置、响应文件、表达式或模板。
存在 '--' 也需核查目标确实支持终止选项，且后续消费者不会再次解析。

## 静态追踪

1. 找输入源到执行调用的变换和校验，区分可执行路径与数据参数。
2. 确认可控值的位置、固定前后参数、选项 parser 和子命令语义。
3. 核查选项能否改变输入/输出目标、读取配置、加载资源或选择处理器。
4. 检查响应文件、配置文件、嵌套命令语言和 PATH 查找顺序。
5. 检查环境、cwd、工作区内容和平台字符转换是否改变解释。
6. 标记实际可达路径、guard 时序和继承权限；静态链仍是候选。

## 基线与对照

先用合法数据确认原功能；随后只变一个可控参数或表示。
使用受控 recorder 或安全诊断捕获子进程实际 argv，不从拼接日志中的空格猜参数。
记录父调用、序列化字符串（适用时）、子实际 argv 及目标解释结果。
在自有临时目录/对象验证是否选择了本不允许的数据或动作。
重复正常基线和反例，确保效果不是固定功能、日志反射或工具自测产生。
配置被解析与配置导致越界效果分开取证。

## 必需证据

- 固定平台/版本/配置和身份。
- 完整调用方式、参数序列与攻击者可控范围。
- 校验看到的值和最终 argv/二次解析语义。
- 实际目标侧受保护效果及正常/未授权对照。
- 继承权限与新增能力，而非“程序有危险选项”。
- 清理状态和可重复复现条件。

## 反证

数组中有空格但子 argv 仍为一个数据参数，不证明新增参数。
用户值位于已确认的纯数据位置，且 parser 不再解释，不独立构成漏洞。
选项被识别但效果只在该主体原有授权内，不证明独立新增权限。
Shell payload 被拒绝不能否定无 Shell 选项注入，反之亦然。
程序报错、OOB DNS 或本地 recorder 成功不证明目标进程 RCE。
缺实际二进制、无法捕获 argv 或未部署代码，保留证明缺口/blocked。

## 停止、清理与修复

不尝试数据删除、外传、模块加载、长期驻留或系统改写。
测试需要未经批准权限或副作用时停止该单元，继续独立可执行候选。
同组合三次无新证据换路，不扩大所有程序选项探测。
修复优先采用语义 API、固定可执行路径和参数允许集合。
将不可信数据限定为目标确认支持的数据参数，不只替换 Shell 元字符。
Windows 按实际父子 parser 测试；错误和配置回退应失败关闭。
