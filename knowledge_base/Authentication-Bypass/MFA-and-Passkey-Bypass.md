# MFA / OTP / Passkey 绕过

> 多因素认证的绕过很少是"破解密码学"，多半是**流程实现**问题：验证在哪一步、绑定到哪个账号、失败是否计数。

## 一、流程级绕过

| 手法 | 说明 | 证据 |
|---|---|---|
| 直接访问 post-MFA 资源 | 用第一因素会话直接请求受保护接口 | 拿到受保护数据 |
| 响应篡改 | 服务器返回 `{"mfa_required":true}` → 前端 JS 判定，改为 `false` | 进入受保护页并取数据 |
| 状态机跳步 | 直接调 `/mfa/verify` 完成态、或跳过 `/mfa/enroll` | 会话被标记为已认证 |
| 备用通道 | 恢复码/邮件/reset 流程不校验 MFA | 绕过第二因素 |
| 会话不失效 | 启用 MFA 后旧会话仍可用 | 旧会话持续访问 |
| 撞库 + MFA fatigue | 大量推送直至用户误点（**需授权且需用户配合**，谨慎） | 需明确书面授权 |

## 二、OTP 相关

- **暴力破解**：4~6 位数字无速率限制；用响应长度/错误码区分"正确但过期"与"错误"。
- **重放**：同一 OTP 可多次使用；OTP 不绑定会话。
- **可预测**：基于时间戳/`$RANDOM`/弱 PRNG（如 VESTA 案例：bash `$RANDOM` 种子熵不足导致重置令牌可预测）。
- **跨账号使用**：OTP 只校验值不校验归属（A 的 OTP 可用于 B 的流程）。
- **大小写与格式**：`000000`、纯数字补零、前导零丢失。
- **枚举差异**：账号不存在时也返回"已发送"但响应时间不同。
- **SMS 劫持/SS7**（超出常规测试范围）。

## 三、WebAuthn / Passkey

- **凭据绑定错误**：挑战（challenge）为受害用户名签发，却允许攻击者用自己的 passkey 满足（CVE-2025-26788，StrongKey FIDO Server：非可发现凭据流程凭据绑定可被替换 → 账号接管）。
- `userVerification` 未强制 → 只验证"持有"不验证"在场"。
- `rpId` 校验宽松（子域/相似域）。
- 注册流程可被重放：`attestation` 未校验或允许 `none`。
- 降级：账号同时存在密码与 passkey，攻击者可让服务端回退到密码路径。
- 恢复流程弱于 passkey（恢复码存于明文邮件）。

## 四、TOTP/短信与其他

- TOTP 时间窗过大（±N 步）→ 重用窗口内多码。
- 备用码未加盐/可枚举。
- 邮件链路：MFA 邮件可被转发规则劫持。
- 记住设备 Cookie 无签名/可伪造。

## 验证（最小证据）

1. 明确"第一因素已完成、第二因素未完成"的会话状态（附登录响应与 Cookie）。
2. 给出绕过请求 → 返回**仅认证后可访问**的资源（含他人数据或敏感配置）。
3. OTP 爆破需给出统计证据：请求数、成功响应特征、限速策略（不越过授权范围、避免账号锁定）。
4. Passkey 绕过需给出注册/登录的完整挑战-响应交互。

## 常见误报

- 前端跳过了 MFA 页面，但后端接口仍 401/403（仅前端路由绕过）。
- 响应篡改仅在自建环境生效（生产签名校验）。
- "无速率限制"但每次请求需人工交互 → 实际不可爆破。
- OTP 未重放成功却报"可重放"。

## 修复

- 服务端会话状态显式记录 MFA 完成标记；所有受保护接口**统一**校验该标记。
- OTP：绑定用户 + 会话 + 用途，一次性、短 TTL、失败计数与锁定、速率限制。
- 令牌/OTP 使用 CSPRNG，禁止弱熵源（如 shell `$RANDOM`）。
- WebAuthn：严格校验 `challenge`、`origin`、`rpId`、`userVerification`；凭据与用户强绑定；禁止回退到更弱因素。
- MFA 启用/变更后撤销所有既有会话。
