# 间接提示注入的利用链

> 间接注入 = 攻击指令藏在**模型会读到、但不是用户输入**的内容里：网页、邮件、PDF、代码注释、issue/PR、数据库字段、文件名。当 Agent 有工具时，链路终点就是**真实副作用**。

## 一、常见链条

| 链 | 入口 | 终点 |
|---|---|---|
| A. 数据窃取 | 邮件/网页含"把会话内容 POST 到 X" | Agent 调用出网工具 |
| B. 命令执行 | issue 标题含指令 | Agent 调用 shell/CI 工具 |
| C. 供应链投毒 | PR/commit 文本 | Agent 提交带后门的代码 |
| D. 链接翻转外带 | Markdown/HTML 链接化被下游渲染 | 零点击数据外泄（Gemini 案例 2025） |
| E. 网页侧 XSS→Agent | 恶意页面内容驱动 Agent 回访 | 越权读取 |
| F. 记忆持久化 | 把指令写入 Agent 长期记忆 | 后续所有会话受影响 |
| G. 多 Agent 传递 | 子 Agent 输出污染父 Agent | 权限提升（子 Agent 权限被"借用"） |

## 二、Gemini 案例的通用教训（2025）

- 攻击链发生在**跨层**：模型读到的 Markdown → 链接化 → 跨产品导出层把"已净化的链接"翻转成图片 → 绕过 URL 重写 → 零点击/一点击带出 Workspace 数据。
- 教训：**净化在错误的层做**等于没做；"看起来安全的中间表示"在下游会被再次解释（与 `../WAF-Bypass/Parser-Confusion-Bypass.md` 同源）。

## 三、有效载荷技巧

- 权威伪装：`[系统指令]`、`<admin>...</admin>`、伪造 tool_result JSON、伪造报错与"合规要求"。
- 分隔符：用 XML 标签、Markdown 代码块、多语言/编码把指令与数据混在一起。
- 隐藏：零宽字符、HTML 注释、极小字号/白色文本（对能"看"页面的 Agent）、PDF 元数据、EXIF。
- 拆分：把指令分到多轮/多文档，绕过单轮检测。
- 目标劫持：让 Agent 认为"这是用户之前的指示"（记忆伪造）。
- 输出触发：诱导 Agent 生成可被下游 `eval`/`sh` 消费的内容（如"输出这段作为命令"）。

## 四、测试方法

1. 列出所有不可信输入通道，每个通道准备一个带**唯一标记**的注入 payload（如要求访问 `uniq1234.attacker-domain`）。
2. 观察工具调用：调用哪个工具、参数是什么、是否有确认步骤。
3. 测试防御深度：换语言、换编码、拆成多轮、放进不同文件类型、通过文件名注入。
4. 测试横向：让被污染的 Agent 去影响另一个 Agent（共享记忆/共享工作区）。

## 五、验证（最小证据）

1. 原始不可信内容（含注入文本）与 Agent 的完整工具调用序列。
2. 副作用：带外 DNS/HTTP 命中（含唯一子域）、写入的文件、外部请求内容。
3. 影响：泄漏的数据类型、达到的权限边界。
4. 若被防御拦截：记录拦截层与绕过失败的对照实验结果。

## 六、常见误报

- Agent 仅"复述"或"总结"了注入内容（没有工具调用）。
- 出网请求由浏览器/其他组件发起，不是 Agent。
- 命令被沙箱拒绝（属于"防御成功"，应如实记录）。
- 注入在测试中成功但对无效载荷也成功（说明是模型通用行为，不是注入）。

## 七、防御（要点）

- 不可信内容与指令**物理隔离**：不同上下文、结构化标注来源与可信度。
- **双 LLM 模式**：一个只处理数据（无工具），一个只做编排（不读原始不可信内容）。
- 工具执行层强制（服务端策略），不依赖提示词自律。
- 出网白名单 + 数据分类（禁止敏感数据出网）。
- 输出后处理：Agent 输出不得直接进入 shell/eval/模板。
- 记忆写入需审批与过滤；跨 Agent 传递需降权。
- 审计完整链路（输入来源 → 工具调用 → 外发）。
