# 跨域攻击链剧本（Attack Chain Playbooks）

> 前面各域是"按技术分类"的知识；本域是"**按任务顺序**"的剧本：把多个域串成一条从入口到影响的完整路径，并规定每一步的判据、证据与回退条件。

## 一、为什么需要剧本层

单点知识在实战中有三个问题：

1. **不知道下一步该做什么**：拿到一个凭据之后，能做的动作分散在五个文档里。
2. **方向选错浪费窗口**：在只有 30 分钟有效期的临时凭据上做无关枚举。
3. **证据链断裂**：每一步都做了却没记录，最后无法说明"我怎么到达这里的"。

剧本层解决这三件事：**阶段划分 + 决策点 + 每阶段最小证据 + 何时停止**。

## 三、剧本通用结构

每个剧本都按同一模板组织，便于 Agent 检索与人类复核：

```text
阶段 0  范围与前置（授权边界、目标标识、时间窗）
阶段 1  进入（获得第一个受信身份/会话）
阶段 2  建图（我是谁、有什么、在哪、有效期）
阶段 3  同层横向（同账号/同集群/同云）
阶段 4  跨边界（跨账号/跨订阅/跨项目/跨租户）
阶段 5  数据面（按分类证明可访问性）
阶段 6  持久化（仅在授权明确时）
阶段 7  证据、清理、报告
```

每个阶段都应写明：**入口条件 → 动作 → 判据（成功长什么样）→ 证据 → 失败/回退 → 关联文档**。

## 四、执行纪律（所有剧本通用）

1. **只读优先**：能用 `get/list/describe` 证明的，不要用 `create/update/delete`。
2. **凭据时效优先**：临时凭据（STS/托管身份/OIDC）过期即失效，先把高价值只读证据取完，再考虑其它动作。
3. **每一步留痕**：命令、时间、目标（账号/资源 ID）、输出摘要。**凭据链必须有图**（谁 → 谁 → 谁）。
4. **不破坏**：不创建长期凭据、不修改生产配置、不导出业务数据；任何写操作需显式授权并记录回滚方式。
5. **明确停止条件**：达到授权范围边界、达到"足以证明影响"的证据、凭据失效、或触发客户事件响应流程时立即停止并报告。
6. **跨云/跨账号尤其谨慎**：越出客户账号即越出授权，除非合同明确包含该账号。
