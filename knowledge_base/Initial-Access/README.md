# 初始访问（Initial Access）总览

> 初始访问的手段在 2024-2026 年发生了明显迁移：从"发一封带附件的邮件"转向 **会话令牌窃取（AiTM）**、**设备码钓鱼**、**诱导用户自己粘贴命令（ClickFix）** 与 **打客服重置 MFA**。四条路的共同点是**绕过多因素认证，而不破解它**。

## 二、授权与合规前置（必须）

1. 明确**书面授权**覆盖：钓鱼（是否允许发给真实员工）、是否允许发外部邮件、是否允许采集凭据、是否允许在受害者终端执行代码。
2. 明确**禁止项**：不得采集真实业务数据、不得修改生产配置、不得使用真实第三方品牌（除授权）。
3. 明确**受益人与联系人**、以及一旦员工上报安全事件时的处置流程（急救联系人）。
4. 若客户有蓝队，约定是否告知（红蓝对抗 vs 纯评估）。

## 三、基础设施要点

- 域选择：关键词域、同形字（homoglyph）、短横线变体、新 TLD、过期好信誉域。工具：`dnstwist`、`urlcrazy`。
- 邮件送达：SPF/DKIM/DMARC 配置、rDNS、域龄（越久越好）、预热、内容避免触发规则；用 `mail-tester.com` 打分（详见 `../Email-Security/README.md`）。
- 落地页：克隆（`gophish`、`Evilginx`）、TLS 证书（Let's Encrypt）、`robots.txt` 阻断、地域/UA 过滤、一次性链接。
- 反侦测：黑名单自查（`malwareworld`）、蜜罐域探测（注册含关键词的诱饵域，看对方是否主动查询）。

## 四、验证（最小证据）

1. 完整攻击链：诱饵内容 → 落地页/载荷 → 获得的凭据/会话/执行结果。
2. 成功判据：**以受害者身份实际访问了受保护资源**（附请求与响应），而非"页面提交成功"。
3. 会话有效性：Cookie 可用于访问，且说明是否包含 MFA 已完成的标记。
4. 计数与统计：发送量、点击量、提交量、成功率；对未成功者不追责、不记录个人敏感信息（合规要求）。

## 五、常见误报

- 邮件送达但被网关隔离（未进入收件箱）。
- 用户提交了假数据（可用明显错误口令验证）。
- Cookie 拿到但已过期/被绑定设备指纹（`__Host-`、绑定 IP）。
- 前端显示"登录成功"但后端拒绝（凭据错误）。
- 用户点击但未提交（只能算点击率）。

## 六、防御视角（写给报告）

- **抗钓鱼 MFA**：FIDO2/passkey（origin 绑定）> 号码匹配 > 推送 > OTP > SMS。
- **令牌保护**：`Token Protection`/设备绑定、条件访问（设备合规、地理、风险）。
- **缩短令牌寿命** + 令牌撤销能力（发现异常一键吊销）。
- **浏览器层**：禁止在非受管网站在登录页输入凭据、密码管理器域名绑定（可阻止 AiTM）。
- **终端层**：限制 `mshta`/`rundll32`/`curl`/PowerShell 等 LOLBin 的执行策略与脚本块日志。
- **流程层**：客服重置 MFA 属特权操作，需二次核验（回拨已登记号码）+ ITDR 告警。
- **意识培训**：把"AI 生成的个性化诱饵"和"要求你粘贴命令"纳入演练。
