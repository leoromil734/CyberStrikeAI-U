# HTTP/2 与 HTTP/3 攻击面

> H2/H3 修掉了 H1 的边界模糊，但引入了新的攻击面：**降级、多路复用、流控制、伪头语义**。

## 一、H2 → H1 降级（H2.CL / H2.TE / H2.0）

- 前端终结 H2，转发到后端时降级为 H1 → 出现第四种长度语义（H2 length）。
- 攻击者可在**同一条流**里构造"前端按 H2 长度、后端按 CL/TE 解析"的请求。
- `H2.0`：请求不带长度头（H2 隐式长度），后端却按"H1 + 无长度 + 有 body"处理 → 后续字节成为新请求（CL.0 式）。
- 案例：Cloudflare Pingora 内部 H1 去同步（2025），攻击者用 H2.0 让任意站点用户被重定向到攻击者站；影响 2400 万站点。
- 检测：用支持 H2 帧控制的客户端（nghttp2、自定义 h2 库）而非 `curl --http2`（降级行为不可控）。

## 二、H2 语义细节

| 点 | 说明 |
|---|---|
| `content-length` 重复/不一致 | 部分实现取首个，部分报错 |
| 非法头名 | H2 中 `Transfer-Encoding`、`Connection`、头名含空格均非法，但代理容忍度不同 |
| 伪头顺序 | `:method`/`:path` 出现在常规头之后，有的实现仍接受 |
| `:path` 特殊字符 | `*`、绝对 URL 形式、`%2f`、CR/LF 编码 |
| 大小写 | H2 头名必须小写，混入大写可能被某层"规范化"成不同头 |

## 三、H2 特有的 DoS 与流控制

- **MadeYouReset（2025）**：在请求已被接纳后触发**流级**协议错误，使服务端发出 RST_STREAM，从而绕过 `MAX_CONCURRENT_STREAMS` 限制，驱动无界后端工作。
- **窗口与优先级滥用**：`SETTINGS_MAX_CONCURRENT_STREAMS`、流依赖树导致的 CPU/内存放大。
- **HPACK 炸弹**：大量请求触发动态表膨胀。
- **CONTINUATION 洪泛**：绕过头大小限制。
- 测试纪律：只在授权范围内、低强度验证，不追求打挂服务。

## 四、HTTP/2 CONNECT 作为内网扫描器

```text
CONNECT 10.0.0.5:443 HTTP/1.1   （在 h2 流内）
```

- 若企业正向代理配置不当，攻击者可用**单条 h2 连接**复用多路 CONNECT 流扫描内网端口，吞吐高且可能躲过只看单流内容的监控（flomb 2025）。
- 先确认代理是否允许 CONNECT 到任意 host（403/200 差异、耗时差异）。

## 五、HTTP/3 / QUIC

- **Quic-Fin-Sync（2025）**：把"最后字节同步"单包竞态技术移植到 QUIC —— 在多个流上缓冲接近完成的请求，再用协调的 FIN 突发同时释放 → 远程竞态条件可本地化利用。
- 0-RTT 重放：早期数据可被重放，非幂等接口若无重放保护即受影响。
- 连接迁移（connection ID）与 NAT 场景下的会话混淆。
- 与代理/负载均衡互操作时的降级链（H3→H2→H1）会叠加多种长度语义。

## 六、检测方法

1. 确认客户端确实在说 H2/H3（`nghttp`、curl 的 `--http2-prior-knowledge`、自研帧控制）。
2. 构造**同一语义的 H1/H2 变体**，对比响应差异（长度、状态、头）。
3. 在走私场景下，用探测法找 V-H / H-V 分歧（见 `Request-Smuggling.md`）。
4. 对 CONNECT：先试探代理放行策略，再验证是否达到内部服务（拿到内部服务的 banner/响应）。

## 七、验证（最小证据）

1. 请求帧序列或可复现脚本（含 ALPN、伪头、流 id）。
2. 影响证据：跨用户影响（缓存/响应错乱）、到达内部服务、或无界资源消耗的可测量差分（谨慎）。
3. 明确上游连接协议（H2 还是 H1），因为修复点不同。

## 八、常见误报

- 客户端自动降级到 H1，实际测的是 H1 行为。
- CDN 边缘拦截导致的差异被误认为 H2 语义问题。
- 代理 CONNECT 返回 200 但目标端口实际未连通（代理先回 200）。

## 九、修复

- 上游连接统一使用 H2+，**禁止降级到 H1**（这是关键）。
- 严格实现 RFC 9113：拒绝非法头名/伪头顺序/重复 content-length；流错误处理不泄露额外工作。
- 限制 `MAX_CONCURRENT_STREAMS`，对 RST_STREAM 滥用做速率与统计监控。
- 正向代理：限制 CONNECT 目标白名单与并发；启用对多路隧道的会话级审计。
- HTTP/3：禁用或严格限制 0-RTT 用于非幂等请求；统一降级链的解析实现。
