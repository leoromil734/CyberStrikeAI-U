# 限流与速率防护绕过

> 限流绕过是"爆破类攻击的前提"（OTP、密码、优惠券、验证码）。**纪律**：绕过证据是"同一账号/同一令牌在绕过手法下不再被计数"，而不是"我发了很多请求也没被封"。

## 一、识别限流的维度

先判断计数键（key）是什么：

- IP / `X-Forwarded-For` / 连接来源
- 账号 / 邮箱 / 手机号 / 用户 ID
- 令牌 / API Key / Session
- 端点路径 / 方法
- 设备指纹 / Cookie
- 全局（网关层）

**只要能影响哪个键被使用，就能绕过。**

## 二、绕过手法

| 手法 | 说明 |
|---|---|
| IP 伪造 | `X-Forwarded-For`、`X-Real-IP`、`X-Client-IP`、`Forwarded`、`True-Client-IP`、`CF-Connecting-IP` 轮换；**每个请求换一个值** |
| IP 变体 | IPv4 的多种写法（`127.1`、`0x7f.1`、前导零）、IPv6 表示、`X-Forwarded-For: 1.1.1.1, 2.2.2.2`（取决取首/末尾） |
| 大小写与编码 | 邮箱 `A@x.com` vs `a@x.com`、路径 `/login` vs `/Login` vs `/login/` vs `/login%2f`、`?a=1&b=2` 顺序变化 |
| 路径变体 | `//login`、`/./login`、`/login;x`、末尾斜杠 |
| 方法/内容类型 | `POST` vs `PUT`、`application/json` vs `text/plain` |
| 参数污染 | 同一参数多次出现，计数取首个、业务取末个 |
| 子端点/别名 | GraphQL 别名与 batched 请求（见 `GraphQL-Bypass-Cheatsheet.md`） |
| 代理与出口轮换 | 多出口 IP、云函数、Tor（授权范围内） |
| 时序 | 分散在时间窗口两侧；利用固定窗口重置（`window` 边界） |
| HTTP/2 | 同一连接多流并行；H2 独有头 `:authority` 变化 |
| 缓存/去重 | 命中缓存的请求不触发计数；`HEAD` 请求 |
| 账号变体 | 大小写、别名 `+tag`（Gmail）、Unicode 归一化、前后空格、`\u0000` |

## 三、OTP/密码爆破的具体做法

1. 确认计数器：固定账号 + 换 IP 是否触发；固定 IP + 换账号是否触发。
2. 找"不计数的通道"：忘记密码、登录、MFA 校验、邮件验证等不同端点常各自计数。
3. 用代理池（授权范围内）在**不超过目标容量**的前提下做低频爆破。
4. 记录：请求数、成功响应特征（状态码/长度/时间），以及 429 出现的位置。
5. 严禁触发账号锁定导致业务中断（除非该项在授权范围内且已与客户沟通）。

## 四、验证（最小证据）

1. 基线：未绕过的请求在第 N 次触发 429/锁定（附响应）。
2. 绕过：变换手法后第 M 次（M > N）仍可继续，且响应与正常一致。
3. 说明绕过的具体键（IP 伪造？路径变体？）。
4. 若同时证明可爆破出有效凭据，给出成功响应（不要写入真实受害者账号）。

## 五、常见误报

- 限流基于"账号 + 业务逻辑"而非 IP，换 IP 无效（需换别的维度）。
- 429 延迟出现（滑动窗口），看起来像"未限流"。
- WAF 只记录不拦截。
- 目标前端有验证码但后端未校验（这属于逻辑漏洞，另记）。

## 六、修复

- 计数键使用**服务端可信**标识（账号 ID + 设备指纹 + 真实来源 IP 取自网关可信层）。
- 忽略客户端提供的 `X-Forwarded-For`（除非来自可信代理并取**最后一跳**）。
- 多维度组合限流（账号 + IP + 端点），滑动窗口 + 令牌桶。
- 路径/方法/编码规范化后再计数；对 GraphQL 按子操作计数。
- 关键操作（OTP、登录、支付）强制 CAPTCHA/风控，并做失败计数与渐进延迟。
- 全局配额 + 单账号配额双层。
