# 幂等键的主体、请求与真实副作用绑定

## 适用与触发

订单、退款、沙箱支付、审批或队列任务采用 Idempotency-Key/requestId/clientToken 时使用。
重点是同一语义操作是否仅发生一次，以及键是否绑定主体、请求和操作。
仅接口返回不同 transaction ID 或两个 200 不证明重复业务效果。

## 前提与版本

记录实际 API/SDK、去重存储、事务与异步消费者版本/配置。
只用授权沙箱、自有测试账号/订单和可恢复的最小测试额度。
确认并发许可、请求上限、速率、处理窗口和回滚方法。
真实资金、客户对象、群发和无法恢复的副作用不纳入本方法。
缺身份/沙箱/并发批准时只读分析并记 blocked 对应单元。

## 正常幂等基线

先记录初始订单、余额/账本、权益、事件和任务状态。
相同主体、相同操作、相同 key、相同正文串行发送两次。
合法实现可能返回缓存、冲突或同一业务结果，依据产品契约判断。
关键是持久化效果一次；响应形状差异不独立代表漏洞。
异步处理需在正常处理窗口读回，不只看提交响应。

## 聚焦对照矩阵

1. same key / same body：串行基线与实际效果数量。
2. same key / different body：金额、对象或操作变化是否被拒绝/区分。
3. cross-user/tenant：键是否暴露别人缓存结果或造成未经允许的操作混用。
4. cross-operation：同键跨接口/步骤使用是否混淆业务边界。
5. expiry：契约去重窗口、业务唯一约束和过期后预期语义分别检查。
6. bounded parallel：仅获准后用少量并发测试原子性，不使用无界洪泛。
7. retry/cancel/partial failure：响应失败与真实提交状态分开。
不同正文被重新执行是否错误取决于契约，不因变化本身机械计洞。

## 原始证据与确认

保存每个请求、响应、key 的受控引用、主体、对象、时间和执行 ID。
读回订单/余额/账本/权益，证明重复或未授权结果的真实数量与净变化。
关联同次尝试的独立 nonce 与下游事件，排除旧任务和缓存。
不同 transaction ID 可能对应尝试记录而非双重扣款，核查最终状态。
同 key 跨用户被接受不等于越权，需证明别人数据或跨主体受保护效果。
只有目标侧新增权限或真实钱/审核等允许的高价值影响才能 confirmed。
同根因按实际边界去重，不按成功响应数统计漏洞。

## 反证与缺口

数据库唯一约束、行锁和一致事务使效果一次，可解释两个成功响应。
去重窗口按约定失效不自动是 replay 漏洞；检查业务语义与攻击前提。
第二请求合法返回缓存结果，是控制生效而非漏洞。
只能多领自己的非敏感权益、没动钱和审核等排除项继续生效。
账本不可读、处理未完成、并发被边缘拒绝时，不用推测填补效果。
长时间异步未闭合记 waiting，到正常窗口且最多 5 分钟转 blocked。

## 停止与清理

未批准并发、健康异常、非预期金额或不确定恢复时停止。
测试矩阵有界，只变一个键绑定轴，不扩大成所有业务压力测试。
清理自有订单/标记并验收账本，正常历史审计不能随意删除。
无新证据三次只结束当前组合，保留其他入口和恢复条件。

## 修复原则

以主体/租户、操作和请求指纹定义键范围。
采用原子持久化和业务唯一约束，兼顾下游异步消费的 exactly-once 业务要求。
定义过期、处理中、失败、重试与响应缓存语义，验证最终副作用而非仅网关去重。
避免泄露其他主体缓存的响应，复测正常合法重试仍可用。
