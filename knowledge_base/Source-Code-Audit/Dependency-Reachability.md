# 依赖公告适用性、引入链与调用可达性

## 适用与触发

已取得依赖清单、锁文件、构建/镜像产物或具体组件版本后使用。
SCA（软件成分分析）回答安装了什么及公告是否匹配，不直接证明目标漏洞。
本方法深化组件情报与白盒分析，不为每个依赖重复全网搜索。

## 前提与版本身份

记录仓库/构建提交、平台、依赖生态、manifest 和锁文件哈希。
区分声明范围、锁定版本、构建实际版本和目标运行版本。
记录扫描器、漏洞数据库版本/更新时间、查询时间及离线/在线来源。
镜像标签可能漂移，优先绑定 digest 与实际层证据。
范围和数据处理许可决定可否上传清单或查询外部服务。

## 依赖图与引入者

1. 定位直接依赖、间接依赖、开发/运行依赖及 optional/平台分支。
2. 从受影响包回溯到引入它的直接依赖和版本约束。
3. 记录 lockfile 中唯一身份、来源、版本、完整性及别名。
4. 检查多版本共存、vendoring、打包合并与容器层替换。
5. 不执行安装或生命周期脚本来补全依赖树；缺图标证明缺口。
6. 说明升级哪个直接依赖、可能兼容性变化和实际修复版本依据。

## 按公告逐项分析

记录 advisory/CVE、生态、受影响版本、修复版本和原始厂商依据。
区分包被安装、被 import、受影响符号被使用、可靠调用图可达及目标效果。
not_imported 不等于安全：动态 import、反射、框架注册和插件可能漏查。
符号 grep 命中不是调用图，不能称 reachable_call_path。
调用图证明也需说明配置、输入可控性和目标部署是否一致。
CVE 前提可能是可选特性、特殊模式或外部可控参数，逐项记录。
公告无修复版本或数据库陈旧时明确限制，不编造可用升级。

## 基线与对照

- 用实际构建/锁文件确定版本，不只依赖 banner。
- 静态数据流将入口、受影响符号、guard 与效果关联。
- 授权隔离环境可比较受影响/修复版本，保留相同正常基线。
- 动态验证只对高信号已适用候选，不遍历执行未知 PoC 仓库。
- 记录真实目标差分和新增能力后，交给 pentest-verification 确认。
- 文本公告、扫描器高分和本地测试成功不能独立确认目标漏洞。

## 必需原始证据

依赖身份、源产物、引入链、公告和数据库时间相互对应。
每一级可达性结论附确切证据和局限，不把工具名当证据。
保存受影响代码位置、参数条件与真实运行映射。
未执行动态验证的项目保持 tentative；不可测项目记录 blocked 原因。
公告评级与目标已证明影响分开，置信度也单独记录。

## 反证与常见误判

安装了受影响版本，但功能未启用，需配置证据才能限定。
前端打包/镜像旧层存在包，不证明当前进程会加载。
只有字符串或安全兄弟调用点，不证明漏洞路径可达或不可达。
动态加载遗漏不能被写成“无可利用性”。
厂商 backport 可能使 banner 版本不足，核查构建补丁。
同根因/同包多个公告按实际根因去重，不按扫描条目数统计漏洞。

## 停止、工具与修复

缺清单、构建或数据库前提时保留缺口，继续独立可执行单元。
trivy 是实际工具配置；govulncheck、Syft 等只作为可选外部依赖，检查环境后使用。
sg-code-search 不是 ast-grep；supply-chain-collect 是资产关联，不是 SCA。
禁止自动安装、更新数据库、pull 镜像或执行陌生包；需要这些动作另获批准。
修复采用可信上游升级/backport，回归正常功能、配置和最小复现。
