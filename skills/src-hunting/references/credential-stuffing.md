# 简单弱口令与产品默认凭据

范围内每个已确认密码入口做一轮，覆盖 Web/管理后台、SSH、数据库、SMTP/IMAP/POP3。不做无限爆破不等于省略简单尝试；侦察角色负责识别、记录与交接，验证角色负责认证。

统一预算与产品细节读根路径 `skills/credential-stuffing/SKILL.md`；精简字典读 `skills/credential-stuffing/references/lite-wordlists.md`。本页不再另设默认口轮次或放大账号配额。

- 身份限用户给定、范围内 JS/页面/响应已有测试身份、受控账号及产品文档默认身份。禁止手机号段、陌生账号枚举和完整 `-L` × `-P`。
- 每账号累计最多 8 次，每入口最多 5 个账号、40 个候选组合、5 分钟；并发 1，间隔至少 3 秒。默认对、空密码、对照及重试全部计入同一预算；更严用户/锁定约束优先。
- 先按产品最多 3 组默认对，再选少量常见弱口令补剩余预算；不能默认对失败就省略简单弱口令，也不能把字典长度当尝试额度。
- 命中、验证码/滑块、MFA、锁定、429 或服务异常即停；不 OCR、不换 IP 续试。缺身份或保护机制记 blocked，不把“未对 SSH、数据库、邮件爆破”当作覆盖结论。
- 密码认证不支持时保留协议证据才能 N/A；CDN 边缘裸 IP 不测试认证，但范围内业务域名与非 CDN 源站服务仍覆盖。Hetzner 等托管商名称不是 CDN 排除证据。
- 保存字典路径/hash、候选数量、实际次数、耗时、停止原因、认证结果和预算内失败对照。口令全部失败只否定所选组合；命中且有独立权限影响才记录“弱口令”，真实凭据复用另记“撞库”。
- SSH/数据库只做只读身份与权限确认，邮件只验证认证能力，不读取邮件、不发信。仅打开登录页、端口开放或工具成功提示均不足以确认漏洞。
