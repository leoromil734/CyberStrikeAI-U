# SRC 价值导向挖洞规则（强制经验）

> 来源：列表注入实战复盘。  
> 职责：保证测全常规漏洞类型、接口参数不漏，只推进真有危害的点。落不落、怎么写只认 `vuln-report-format.md`。  
> 进站节奏（说清这摊、JS 抽钥匙、有差分面、有会话对象图、中危升链）认 `dig-scope-workflow` §4；本文件管「挖什么、每类最低探针、力气怎么分（§1.1）」。

---

## 1. 挖什么：真价值优先

有价值 = 能打到高危/严重那档：跨租户/跨用户读或写、未登录出业务敏感、低权到平台管理员、注入出他主体、完整链（跨用户写、进号、命令跑起来）。怎么分力气、进站先砸哪，只认下面 §1.1。矩阵有入口仍勾或 N/A，不删类型。

**「管理员」语义（易误读，务必记准）：**
- 用户说注意「管理员」= 盯 **官方/平台级管理员权限** 是否可到，以及提权链
- **不是**「当前是租户 ADMIN 所以能看的都不算洞」
- 租户 ADMIN 是**跳板视角**：用本租户基线（如会话 total=2）对比注入/越权后是否变成海量/他租户

### 1.1 力气怎么分（先打更容易高危/严重的）

不删类型、不加第五件套、**XSS 与注入/SSRF/RCE 同等催**。进站顺序认 `dig-scope` §4；本表只管力气先砸哪。

| 先打 | 说明 |
|------|------|
| 未登录出他人/他主体 | 不登录出名单/详情/附件/证件。**未授权通了再换 id（不限字段名）**（`dig-scope` §4.2.3）。「打开了但没有密钥」只停敏感路径，不停业务数据口。文件通道开了先看能不能读敏感文件或执行，不能就停 |
| 有影响的默认口 | 管理面、SSH、数据库、邮件、中间件先试产品默认对，再做简单弱口令，共用 `credential-stuffing.md` 的 8/40 次、5 分钟小预算，不另开默认口轮次。命中或验证码/MFA/锁定/限流即停，认证成功且权限有影响才记 |
| 认证接管 | 发会话 / 重置 / 改绑 / 换票；进号或改密才算（`dig-scope` §4.2.2） |
| 换 id（不限字段名） | 没号：未授权通了再换。有号：带着会话换（`dig-scope` §4.2.3）。他主体出现算打穿 |
| 有号写/逻辑 | 加 `role`、改金额/状态、跳审核、券/库存并发；盯租户身份能不能到**平台/官方**管理员 |
| 四件套 | 有条数/回显打注入；会拉网址打 SSRF；有命令/模板/导出/报表/文件名跟 RCE。登录墙后面的业务参，有会话就打，不要整段 N/A。XSS 只在能打到他人会话时测 |

**没号：** 未授权敏感数据 → 管理面/中间件默认口 → 未授权通了再换 id → 认证口 → JS 钥匙 → 有差分面的注入/SSRF/RCE。  
**有号：** 带着会话换 id，只继续手机号、证件或正文。只出标题、摘要、昵称就停。登录后的查询、过滤、排序、导出、报表、文件名照样打注入和命令执行，不要因为匿名时是登录墙就整段 N/A。钱、审核、改密、接管才打逻辑。XSS 打不到他人会话不测。

**清单里已经有的执行面不许后置到不做：** 上传、导入、预览、导出、报表、模板、命令参数、反序列化，换 id 没打穿也要给终态（打完或 N/A+原因）。没有这类入口才 N/A。  
**有关联证据的疑似下游**（范围内页面/JS/接口/证书带出的 host）进清单后走同一顺序，不只记资产。仅名称相似、CDN/第三方库、已坐实参股不测。  
**有入口仍测，不当主业：** 能传能下但读不到敏感文件也不能执行的，不测。C 端登录框弱口令仍按有界撞库，没进号不记。

## 2. 挖到这些别停在半截（测法）

落不落、标几级只认 `vuln-report-format.md`。这里只说怎么继续挖：

- 文件通道开了 → 立刻转业务 API、可执行/路径/SSRF 链  
- 发码接口通了 → 跟认证链：回包有没有码、码绑不绑号、重置换不换用户（`dig-scope` §4.2.2）  
- 滑块过了 / 能试密 → 表单壳停，打空密、跳步、重置、改绑  
- DSN/配置只有 host、没账密 → 继续找完整凭据；有账密/AKSK 当钥匙打：假值对照证明生产认，认钥枪须带出身份或列表，再打不影响线上的只读例（第一枪已带出则换另一类只读）。人账号出会话后同样打只读例，定级认 format。证伪当没钥。抄到就停手交报告 = 禁止。手机号加解密钥不当钥匙（落不落认 format）  
- CORS **不挖**（见 `cors-vuln-report-priority.md`）  
- 本职可读、公开静态、接口 200 有 JSON → 转跨用户/注入/提权  
- 回包里冒出 id / 下载地址 / token / 内部 host → 进本站队列再打（`dig-scope` §4.1.3）  
- **中危落了先升链再换站**：同一对象还没走到写 / 跨用户敏感正文 / 接管 / 可执行，先跟。低价值面（只有标题摘要、打不到他人会话的 XSS、没动钱和审核的逻辑）不升链，直接停。  

## 2.2 挖洞偏好禁令（永久）

- **禁止**挖 CORS  
- **禁止**把会话精力钉在未授权读/同构列表上，连续多日不碰 **注入 / SSRF / XSS / RCE**（细则见 `dig-scope-workflow` §4.2.1）。
- **必须**按 §3 类型矩阵推进：未授权、越权/IDOR（有会话与四件套同硬，见 `dig-scope` §4.2.3）、注入、SSRF、RCE 链、凭证泄露、弱口令（每个登录口一次有界撞库，见 `credential-stuffing.md`；禁止全号段和无限试密；**JS/页里演示号当钥匙**）、敏感路径、XSS、上传、穿越、CSRF、提权、逻辑、**认证/任意登录/接管**（见 `dig-scope` §4.2.2）——**各种都要挖**（与 `dig-scope-workflow` §4.2 并集；**不含 CORS**）。
- 未授权读出一批后 → **立刻**对同批接口跑完 §3 注入参数表 + SSRF URL 参 + XSS 回显/存储 + RCE Sink（见 dig-scope §4.2.1，打在有差分面上）；禁止未授权写完就换站且四件套零 payload。
- 有会话后禁止只喷 `'`：对象图 / 换 id / 加字段 / 跳步 按 `dig-scope` §4.2.3。

## 3. 测全：类型矩阵（每轮目标至少过一遍）

对当前目标接口清单，按类型勾选，**不能只测信息泄露**。  
进站顺序认 `dig-scope-workflow` §4（先说清这摊，再抽钥匙、建清单、再测；本轮完成换站）。

| 类型 | 探针要求（有入口就打完；无入口 N/A+原因） |
|------|----------|
| 未授权 | 关键读/写 `credentials:omit`。通了再换 id（见下行） |
| 越权/IDOR | **只测能出手机号、证件或正文的。** 只读到标题、摘要、昵称，或日记/说说/相册只有标题或摘要 → 不测、不升链。有手机号、证件或正文才换 id。 |
| 注入 | 能看出条数变、内容变、或会去拉一个网址的口：上面 **每个** 查询/过滤/排序/关键字、导出/报表参数都测（基线 → 探针 → 差分，详见 §4）。匿名只回「请登录」、没有业务字段 → 缺身份的对应单元记 blocked。有会话后同一口的业务参仍要打，不得整段 N/A。空列表 / 报错 / 超时不是请登录，对照见 `dig-scope` §4.1.2；没差分就停。**按栈选探针**：JSON/Mongo 打操作符；搜索框打 ES 或列表 OR+total；Java 打 HQL/SpEL；有模板打 SSTI；SQL 面仍走 `'`/布尔/延时/WAF 编码。被拦了换位置（query/json/header/path）。用户名/密码框不是业务参；登录接口上的 `tenant` / `corpId` / `moduleId` 有就打（`dig-scope` §4.1.1）。 |
| SSRF | 全部 URL/回调/webhook/file/fetch/import/preview/proxy 参：内网/元数据/外带 |
| RCE / 代码执行链 | 命令/表达式/模板/反序列化/导出/报表/文件名/危险上传等 Sink：有入口跟到执行或证伪。换 id 未打穿不得把本行留空 |
| 凭证/密钥泄露 | 抄到 token/AKSK/私钥/连接串后：假值对照，认钥枪须带出身份或列表，再打不影响线上的只读例。人登录后台出会话定级认 format。占位/过期/真假同一句、调不到验钥口、手机号加解密钥 → N/A（不写，认 format）。 |
| 撞库 / 默认口 | 范围内 Web/管理面、SSH、数据库、SMTP/IMAP/POP3 和中间件按 `credential-stuffing.md` 做一轮默认对 + 简单弱口令，统一预算（每账号8次/每入口40组合/5分钟、并发1、间隔≥3秒）。命中/验证码/MFA/锁定/429/异常即停，禁止全号段与全字典组合。缺身份/保护机制 blocked，无密码能力须协议证据 N/A；认证成功且权限有影响才记。JS/页里已知测试号可以作为身份。 |
| 敏感路径 | 只在出密钥、口令或可当会话的票时继续。没有密钥、只有内部路径或配置项 → 不测 |
| XSS | 只测能打到他人会话的。反射打不到他人会话、存储只在自己资料或评论 → 不测 |
| 上传 | 有上传/导入点先做两类最小探针：可读路径和可执行后缀/解析。两类都否定仅否定当前假设，不代表上传能力整体安全；按真实存储授权、文件解析、异步处理能力转 `file-upload-test.md` 现有方法。只验证敏感文件、跨主体存储权限或执行等高影响；只能上传或下载、读不到敏感文件也不能执行 → 不测、不报、不升链；只在本身份权限内的自有对象也不报、不升链 |
| 穿越 | 只读敏感文件或可执行。只读到非敏感文件 → 不测 |
| CSRF/鉴权参数 | 不测 Cookie 属性，不测只害自己的 CSRF。跨用户写没改钱、没改密、没接管 → 不测。改到钱、改密或接管才测 |
| 提权 / 逻辑 | 钱、审核、改密、接管、加 role/isAdmin 才测。只改自己的状态、积分或优惠券，钱和审核没动 → 不测。并发只让自己多领一次、没打到别人余额 → 不测。打到别人余额或审核才测 |
| 认证 / 任意登录 / 接管 | 清单有发会话 / 重置 / 改绑 / 换票 / 2FA → 按 `dig-scope` §4.2.2 勾完。用户名/密码框不当四件套 |
| CORS / 开放重定向 / 安全头 | **不测。** CORS、缺安全头、点击劫持、Cookie 缺 Secure/HttpOnly、证书过期、弱 TLS、缺 HSTS、没带出会话的开放重定向，一律不发请求。开放重定向带出会话才测 |
| 其它现场面 | 矩阵未点名的现场面照样测；认证口走上一行 |

## 4. 接口与参数：禁止漏字段

1. 打开真实页面 → 抓**完整**请求（query + body）
2. 列出全部 filter/id 字段，**短枚举字段也要测**（如 `vote`、`answerType`、`status`）
3. 有差分面的口上，每个过滤参最低矩阵（只回「请登录」的口不在此列；用户名/密码框不是业务参，见 §3、`dig-scope` §4.1.1）：
   - 正常值 / 空 / 非法值
   - 按栈选探针：SQL 面 `'` / 布尔；JSON 面操作符；搜索框 ES/OR+total；Java HQL/SpEL；有模板 SSTI
   - 延时（按库型）
   - WAF 编码：`%0a` `%0d` 双写 注释 大小写 混用；**还要换位置**（query / json / header / path）
4. **差分是硬证据**：本租户基线 total/条数 vs payload 后 total/他主体字段

**教训实例（列表筛选项）：**
- `vote`：用户提示存在注入；当前多 405，可能已修，仍要回归
- `keyword=1%0aor%0a1`：WAF 可绕，total 从 2 → 数千万级，跨租户元数据 → **真 SRC 点**
- 漏测原因：只验「有没有数据」，没做「全参数注入矩阵」

## 5. 执行节奏

1. **资产齐套**：域名、登录态、菜单路由、JS 抽 API（含盐/密文 id/hidden 路由/演示号）、真实请求参数表；回包里的 id/url 补进清单  
2. **价值排序**：按 §1.1 力气先打未登录他主体 / 认证接管 / 换 id / 四件套（含 XSS）；信息泄露后置且降级表述  
3. **类型扫全 + 参数扫全**（有差分面优先）；新接口入队即测；有会话先对象图再喷参；CSRF/能传能下/登录框弱口令不当主业  
4. **只留可复核证据**（请求、差分表、关键字段）；不堆无效「收获」  
5. 打成了按 `vuln-report-format` 落盘；中危同一对象先升链；dig 不替代正文

## 6. 自检（交结论前）

- [ ] 有差分面的口上，是否每个 filter 参数都做过注入/越权差分？只回「请登录」的有没有误喷？  
- [ ] 未授权是否用 omit 测过（业务接口）？  
- [ ] 跨租户/他用户是否测过（不是只测本租户 ADMIN 可读）？单号是否用回包/列表里的 id，而不是放弃？  
- [ ] 有会话时对象图 / 换 id / 加字段 / 跳步是否打了（`dig-scope` §4.2.3）？  
- [ ] 上传是否跟到可执行/SSRF/业务越权，没停在能传能下？  
- [ ] 发码/滑块之后认证链是否按 `dig-scope` §4.2.2 打过？  
- [ ] 「管理员」是否误判成「权限内不算洞」？  
- [ ] WAF 405 后是否换编码/换参数位置再试？注入是否按栈选了探针？  
- [ ] **有无误挖 CORS？**（不挖）
- [ ] **本轮是否偏科只挖未授权读？** 是否每个 path 喷 `'` 充四件套勾完？  
- [ ] **注入**：有差分面的查询/过滤参数是否做过基线+探针+差分？  
- [ ] **SSRF / XSS / RCE**：URL 类参、回显/存储点、exec 类 Sink 是否真打过或 N/A+原因？有无连日空窗？  
- [ ] 中危落了同一对象有没有先升链？回包线索有没有进清单？  
- [ ] 抄到的凭证是否假值对照、认钥枪带出身份或列表，并有不影响线上的只读例？有没有把手机号加解密钥当洞写？人账号进号有没有只读例？

## 7. 一句话

**测全类型与全参数；力气按 §1.1 先打更容易高危/严重的（未登录他主体 / 接管 / 换 id / 四件套含 XSS）；四件套打在有差分面上、按栈选探针；有会话则越权/逻辑与四件套同硬；认证口按 `dig-scope` §4.2.2 勾；CORS 不挖；用基线差分证明跨权/注入。中危先升链。落不落只认 `vuln-report-format`。**
