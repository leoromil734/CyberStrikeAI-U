# 源码感知白盒流程

源码用于缩小动态验证范围，不替代运行时证据。先确认当前服务实际运行的版本、构建与配置，避免分析未部署代码或诱饵分支。

## 1. 运行时对齐

- 定位启动入口、路由注册、中间件顺序、配置来源、部署清单和构建版本。
- 将公开 URL、方法、认证态与源码 handler 对齐；无法证明正在提供服务的代码只标记为静态线索。
- 记录环境差异：feature flag、反向代理重写、租户配置、队列/worker 和外部依赖。

## 2. 静态映射

按以下顺序建立窄链路：

1. 输入源：路由参数、JSON、header、文件、消息、Webhook、定时任务。
2. 变换：解析、规范化、校验、序列化、模板和查询构造。
3. 安全决策：认证、中间件、对象归属、角色/租户/scope 检查。
4. 危险汇：数据库、命令、文件、模板、网络请求、反序列化和权限变更。
5. 副作用：缓存、队列、重试、异步 worker、审计与回滚。

每条候选保存 `entrypoint → transforms → guard → sink/effect`，同时标记真正控制变量和否定条件。

## 3. 动态闭合

- 从静态链生成最小请求，先复现正常基线，再只改变一个安全相关变量。
- 鉴权候选使用匿名/低权/其他主体对照；注入候选使用安全回显、时间或 OOB 证据。
- 如果运行时行为与源码冲突，优先检查构建版本、缓存、代理重写和配置；仍不一致时以运行时证据为准。
- 只有目标侧可复现且影响成立才记录漏洞；静态可达但动态不可达写 tentative 或负结果。

## 交付

输出路由/入口映射、数据流链、安全检查位置、动态请求与响应证据、运行时差异、已否定分支和建议修复位置。修复建议优先放在最靠近安全边界的共享校验层，而不是逐入口打补丁。
