# API 授权差分矩阵

至少准备两个不同主体的测试对象和身份。只有单一高权限身份时，不能确认水平越权或低权功能越权。

## 矩阵

| 测试 | 基线 | 单一变化 | 正证据 |
|---|---|---|---|
| BOLA/IDOR | A 访问 A 对象 | 对象改为 B | A 获得 B 的数据或副作用 |
| BFLA | 管理员执行管理动作 | 身份改为低权 | 低权动作成功且状态变化 |
| 字段级授权 | 正常可写字段 | 增加受保护字段 | 字段实际持久化或改变权限 |
| 过度暴露 | 高权读取敏感字段 | 身份改为低权 | 低权仍收到不应可见字段 |
| 批量操作 | 单对象授权 | 批量中混入他人对象 | 未授权对象被返回或修改 |
| GraphQL | 自有 node/mutation | 换全局 ID 或字段 | 跨主体数据/动作成功 |

## 执行注意

- 不只比较状态码；比较对象主体、敏感字段、数据库/后续 GET 和审计事件。
- 创建各自测试数据，避免访问真实用户敏感记录。
- ID 可预测只是前提；必须证明服务端授权检查缺失。
- 404、空数组和字段裁剪可能是有效防护，也可能是缓存/租户上下文错误，需要重复基线。
- 一个共享授权中间件缺陷导致多个 endpoint 失效时，按根因合并报告。

## 业务状态

写操作前记录初始状态和回滚方式。对订单、优惠、余额、邀请和审批等流程，同时控制身份、对象和状态；不要在一次请求里同时改变三个变量。
