# API 业务流与服务端能力

## SSRF 与第三方回调

关注 URL 导入、Webhook、头像、文档渲染、云资源连接和代理接口。使用唯一 OOB 标识、授权测试服务或低风险内网目标证明服务端请求；验证重定向、DNS 解析和协议限制时一次只改变一个变量。

第三方响应、Webhook 签名和透传字段不能被默认信任。测试签名覆盖范围、重放窗口、事件顺序和主体绑定，但避免向真实第三方发送敏感数据。

## 业务流

对下单、领券、邀请、审批、验证码、退款和配额流程绘制状态机：

```text
state + actor + object + action → next_state + side_effect
```

测试缺失前置、重复提交、顺序颠倒、幂等键、并发窗口和服务器端价格/权限字段。只用测试对象和最小次数证明状态错误，不进行资源耗尽。

## GraphQL

检查 resolver 级对象/字段授权、mutation 副作用、全局 ID、alias/batch 和订阅通道。深层查询与批量请求先评估资源风险；DoS 只做配置与小规模阈值证据。

## 注入与解析

JSON、header、query、GraphQL variable 和上传元数据可进入数据库、模板、命令或反序列化汇。加载对应 Web reference 做单变量差分，不把 API 错误堆栈直接视为可利用注入。

## 资源与自动化滥用

证明单个主体可以越过业务限制即可；停止在最小样本，记录速率、配额和副作用。不要通过大规模注册、验证码轰炸或批量交易证明问题。
