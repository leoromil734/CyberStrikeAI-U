# Web 服务端处理

本页覆盖服务器侧请求、文件、上传、路径、解析器和反序列化候选。先识别实际 handler 与副作用，再选择专项验证。

## SSRF 与回调

- 入口：URL 导入、Webhook、头像、PDF/截图、代理、feed、云资源同步。
- 基线：正常外部 URL 与明确不可达 URL。
- 正证据：唯一 OOB、授权内网内容、可控重定向链或服务端来源特征。
- 否定时说明协议、DNS、重定向、出口策略和时间窗口；无 OOB 不等于所有 SSRF 均不存在。

## 文件读取与路径

- 先区分 URL 路由规范化、反向代理规范化、应用路径拼接和真实文件系统路径。
- 使用安全、非敏感的已知文件或应用自有静态资源验证路径差分。
- 只有读取越过预期根目录的内容，才证明路径穿越；错误页大小差异只形成线索。

## 上传与解析

记录文件名、Content-Type、magic bytes、存储位置、下载域、服务端转换和最终渲染上下文。分别验证：

1. 是否只存储或会被解析。
2. 是否可控访问路径和响应类型。
3. 是否发生服务器侧执行、模板解析或浏览器执行。
4. 是否跨越租户/对象边界。

不要把“成功上传”自动等同于代码执行。

## 反序列化与模板/转换器

需要证明不可信数据到危险解析器的完整链，并优先使用无副作用标记、错误差分或受控回调。组件版本匹配只能提示可能 gadget，不能代替可达性和目标侧影响。

## 服务端路径与方法差异

遇到代理和应用对 `..;`、PATH_INFO、重复斜杠、编码路径或 method override 处理不一致时，一次只改变一个规范化变量，并比较“边缘层拒绝、应用路由命中、实际受保护动作”三个层次。仅从 403 变 404 只证明处理层变化，不证明权限绕过。
