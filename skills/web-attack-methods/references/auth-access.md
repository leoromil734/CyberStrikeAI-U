# Web 认证与访问控制

目标是证明身份或对象边界被跨越，而不是证明“持有有效会话可以访问已授权功能”。

## 身份基线

为每个请求记录：匿名/用户 A/用户 B/管理员、租户、scope、会话来源和预期权限。优先使用以下最小对照：

- 无凭据 vs 有效凭据。
- 用户 A 自有对象 vs 用户 B 对象。
- 低角色 vs 高角色相同动作。
- 正常 token vs 过期、撤销、错误 audience/scope token。

## 候选类别

| 类别 | 关键变量 | 正证据 |
|---|---|---|
| 认证绕过 | 凭据缺失/无效、流程步骤、服务端会话 | 未经有效认证获得新会话或受保护能力 |
| 对象级授权 | 对象 ID/主体 | 读取或修改其他主体对象 |
| 功能级授权 | 角色/动作 | 低权执行管理能力并产生可验证副作用 |
| 会话管理 | 固定、撤销、绑定、并发 | 服务端接受本应无效或不属于该主体的会话 |
| JWT | alg、key 选择、claim、scope/audience | 篡改后的 token 被服务端接受并新增权限 |
| OAuth/OIDC | redirect、state、PKCE、token 绑定 | token/code 被错误主体获取或复用 |
| SAML | 签名覆盖、断言选择、受众 | 未受信断言影响服务端身份或权限 |

## 密码重置与 MFA

只有跳过验证、替换目标主体、重用/预测服务端 token 或绕过服务端状态机，才构成边界突破。已取得用户有效会话后读取该用户自己的资料或 MFA 配置通常只是既有权限或纵深防御问题。

## 交付

保留两组主体、两组请求、关键响应字段和后续状态验证。避免只根据 200/302 判断成功，也不要把同一根因后的多个正常接口拆成多个漏洞。
