# 边缘层与反向代理差分

目标是归因响应来自 CDN/WAF、反向代理、应用框架还是业务 handler，避免把边缘拒绝误判为接口不存在或漏洞成立。

## 分层证据

记录响应头、状态、大小、时序、TLS/HTTP 版本、错误页特征和唯一请求 ID，并建立：

1. 已知正常业务路径。
2. 已知不存在路径。
3. 当前候选路径。
4. 仅改变一个变量的对照。

从固定 CDN 502 变为 nginx/Tomcat/Spring 错误只证明请求到达了不同处理层；还需证明受保护业务动作或数据实际成功。

## 规范化差异

按单变量测试路径编码、分号、PATH_INFO、重复斜杠、header 重写和方法变化。对每个请求记录边缘匹配路径与应用最终路由。不要同时修改路径、方法、header 和编码。

## WebSocket 与异步入口

HTTP 路由限制不一定覆盖 WebSocket/STOMP/SockJS 或消息 worker。只有在范围内确认对应 endpoint、消息目的地和服务端处理后再测试；消息被接受不等于受保护动作完成，需查询后续状态或审计事件。

## 客户端指纹诊断

出现 `cf-ray`、Cloudflare 或普通 403 只表示存在边缘层。只有满足以下条件才加载 `cdn-tls-fingerprint`：

- 标准客户端低速稳定停留在边缘。
- 同一 IP/账号/请求状态下浏览器到达业务层。
- Cookie、Authorization、CSRF、方法、请求体、重定向、JS challenge 和限流已对齐或排除。
- 唯一变化是客户端 TLS/HTTP2 栈，且结果可重复。

确认后仅替换受影响请求，不把 curl_cffi 当默认客户端。

## 源站与非标准端口

只能在明确 in-scope 资产中验证历史 DNS、证书或端口线索。源站直连必须保留 Host/SNI 对照，并避免把共享 CDN 节点或第三方服务纳入测试。
