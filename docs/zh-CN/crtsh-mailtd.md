# crt.sh 资产发现与 Mail.td 临时邮箱

## crt.sh 被动来源

新增工具 `crtsh_search`，输入明确的 `domain`（例如 `example.com`），不接收 URL、IP、端口、通配表达式或任意查询。工具查询固定的 crt.sh 上游，合并域名自身与子域证书结果，规范化和去重候选，仅保留查询域及其子域。

- 域名侦察在 FOFA 首步之后尽早使用；本轮已有同范围证据则复用。
- 保留证书 ID、有效期、原始名称、查询状态和响应摘要，用于原件/库存追溯。
- 历史、过期及通配证书参与发现，但一律是待验证候选，不证明 DNS 存在、当前存活、归属或主动测试授权。
- 结果接入已有原件与侦察库存机制。`success` 只表示本次有界查询成功，不代表全量资产覆盖；`partial/truncated`、错误和未覆盖范围必须保留。
- 超时、限流、错误页、响应限制有明确反馈；达到有界重试上限后换异构来源，不无限请求。
- 普通侦察角色及相关子角色已经加入工具白名单；自定义受限角色按需加入 `crtsh_search`。
- 部署时将 `scripts/crtsh-recon.py` 发布为 `/opt/cyberstrike-tool-runtime/scripts/crtsh-recon.py`，工具 YAML 默认使用该只读运行目录。bubblewrap 不允许直接读取应用源码目录；其他安装位置需同步调整工具参数及允许的只读运行目录，不能为此暴露整个应用配置目录。

## 临时邮箱全局工具

工具名 `temporary_email`，在各角色工具列表中可见，但调用仍要求 `agent:execute` 权限及可访问的当前会话。全局可用不等于能访问供应商账户下的全部邮箱。

操作：

- `domains`：获取可用域名，服务端缓存5分钟。
- `create`：传入当前授权自助注册的 `target_url`，默认 `slot=primary`。需要邮箱进入认证业务面时可创建；已有身份先复用，只有必要的高价值 A/B 对照才用 `secondary`。
- `list`：列出本会话的邮箱及状态，包括重启前创建的邮箱。
- `messages`：传入 `mailbox_id`，分页查看邮件摘要；每页最多30条，`has_more` 指示可继续分页。
- `read`：传入 `mailbox_id` 和 `message_id`，读取纯文本正文及供核对的 HTTP/HTTPS 链接。
- `wait`：支持 `sender_contains`、`subject_contains`、RFC3339 格式 `after`。默认60秒，最多120秒、5次查询；只检查最新一页，超时不等于注册失败或无历史邮件。
- `delete`：传入 `mailbox_id` 和 `confirm=true`，只删除本工具创建的邮箱，不修改目标站账户。

邮箱工具本身不会提交目标站注册、点击验证链接、下载附件或执行邮件中的内容。正常注册流程须核对当前目标、发件方、链接域名；邮件正文和链接均为不可信数据。遇到图形/滑块验证码、费用、邀请、实名、审批、锁定或限流时停止相应身份线，不绕过。

### 隔离与预算

- 邮箱按当前会话绑定，即使同一用户可访问多个会话，也不能跨会话传入邮箱 ID 读取。
- 仅提供两个创建槽位 `primary/secondary`，数据库唯一约束防止并发或重试重复创建。重复 `create` 返回已有槽位，删除不重置创建预算。
- 邮箱密码由服务端随机生成，仅发送给 Mail.td；API 密钥和邮箱密码都不返回给模型，也不写入归属表。归属表仅保存邮箱 ID、地址、状态、注册目标 origin 和时间。
- 创建响应丢失时保留 `pending`；30秒后对同槽位 `create` 只按随机地址查询确认，不重复 POST。供应商明确拒绝后不会自动换邮箱冲额度，应处理配置/配额问题后再继续新任务。
- API 密钥始终发往固定的 `https://api.mail.td`，拒绝重定向，错误不回显响应中的密钥。响应最大2 MiB，输出正文最多12000字符并标注截断。
- 默认请求速率低于官方上限；429/403/额度不足直接报告，不自动绕过或反复注册。账户需具备相应权限和可用月度 operations 额度。

## 服务器密钥配置

推荐通过环境变量 `MAILTD_API_KEY_FILE` 指向仅服务用户可读的密钥文件；也支持 `MAILTD_API_KEY`。配置文件变量优先，文件只能包含 token 本身。

本次部署使用 `/etc/cyberstrikeai/mailtd-api-key`，目录权限0700、文件0600。systemd 的服务覆盖配置只保存 `MAILTD_API_KEY_FILE` 路径，不保存 token。修改或轮换密钥后重启应用。

密钥不写入版本库、工具 YAML、模型输入参数或全局邮箱清单。未配置时工具明确报告配置缺失，不退回读取其他人的邮箱。

## 官方接口依据

- [Mail.td 官方文档](https://docs.mail.td/)
- [官方机器可读文档](https://mail.td/llms.txt)
- [官方 OpenAPI](https://api.mail.td/openapi.yaml)

采用 `/api/domains`、`/api/accounts`、`/api/accounts/{account_id}/messages` 等统一接口及 Bearer token 认证。创建邮箱官方限制为每秒1次，其他接口每秒10次；另有按月 operations 额度。邮箱只收不发，保留时间及账户生命周期由供应商套餐决定。

## 验证范围

单元测试使用本地 HTTP 服务和固定邮件，不发送真实注册请求。覆盖域名来源、重定向/敏感错误处理、响应上限、会话隔离、并发创建、重启复用、创建结果不明时恢复、删除确认、HTML安全呈现和角色可见性。供应商实际账号状态、额度与目标站是否接受临时邮箱需要运行时核实。
