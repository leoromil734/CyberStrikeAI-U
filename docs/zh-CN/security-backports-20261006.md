### C2 文件、加密与会话隔离

参考官方 `ed47ee20`、`bdefa535`、`d9a111ff`、`338dcdbc`、`fa4e5ef4`，以及 `079ba0d2` 的处理器授权兜底：

- 上传任务标识、结果文件后缀和最终路径受到约束，拒绝路径穿越和 Windows 备用数据流标识。
- HTTP 结果解密失败后直接拒绝，不再回退接收明文结果。
- 结果回传绑定任务、会话和监听器。
- HTTP 增加独立会话凭据；数据库只保存 SHA-256 哈希。已存在的未绑定身份不能被仅知道 UUID 的客户端认领。
- HTTP 心跳、任务领取、结果回传和文件读写均校验会话身份。
- TCP 文件读写也要求连接已绑定会话，并校验上传任务、下发文件与该会话/监听器的归属。文件授权根据任务载荷顶层 `file_id`，而不是猜测文件名或接受嵌套同名字段。
- 生成内容前验证回连主机格式，维持合法 IP/主机名及地址拼接兼容。
- C2 任务取消、等待处理器补充权限兜底；原正常路由已有 RBAC 对象授权，本次不将其误报为原有路由越权。

兼容说明：

- **旧 HTTP 客户端没有独立会话凭据，升级后需重新生成。** 新实例不自动接管旧会话或旧任务；历史记录保留。
- 模板修改仅用于传递认证字段，没有增加命令、载荷或调度功能；未运行生成客户端。
- 新增 `c2_http_session_auth` 表，不清空旧表、不替换整个数据库初始化逻辑。
- 未同步官方 watchdog、离线任务收尾、TCP 串行调度等普通稳定性改动。
