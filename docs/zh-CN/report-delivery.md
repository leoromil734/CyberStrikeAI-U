# 报告提交、阶段交付与运行终态

## 交付与完成分开判定

- **候选报告**：模型正文或 `exit.final_result` 是请求收尾的材料，不是覆盖证明。候选全文在过程记录保留，并在前端单独折叠显示；不与已核实成果混写。
- **完整报告**：执行、覆盖及报告正文检查通过后，才可设置 `finalizable=true`、`finalized=true`。全面评估不能用一句“已完成”代替报告。
- **阶段报告**：执行因失败、取消、超时或续跑预算耗尽而确实停止时，必须交付含实际保存成果、证据引用和未完成限制的报告。状态保持 `blocked`、`failed`、`timeout` 或 `cancelled`，不伪装评估成功。
- 等待人工审批不是运行完成；用户取消、总时限等终止条件继续有效，不为等待报告无限执行或恢复已取消任务。

## exit 与收尾顺序

Deep/Supervisor 仍使用 Eino 原生 exit；主路径成功执行 exit 只提交本段报告候选，历史 exit、子角色 exit 和未执行参数不能冒充当前提交。

收尾按以下顺序执行：

1. 检查整个会话的后台工具，而不是只看最后一段工具 ID。工具仍在运行时先等待，在原请求截止时间和各工具时限内等待真实终态；数据库读取失败不得当作已完成。
2. 等待当前评估的持久化结果入库队列，避免原件尚未解析就要求模型补台账。
3. 重新续跑读取完成结果、处理可执行缺口并形成报告。`ReportSubmitted=true` 或正文像报告不再单独阻止续跑。
4. 原始候选过多或连续无独立证据进展时，停止机械补写，切换为范围核实、分类去重及实际验证。保持原始库存与来源，不统一写 N/A，不通过缩小计数伪造覆盖。
5. 检查通过才交完整报告；触及真实终止边界时交阶段报告，然后发送 done。done 表示本轮停止，不表示评估成功。

外层自动续跑仍最多八段（覆盖工作）或两段（其他交付修复），并共享本次请求总时限。分类/验证续跑不启动旧的十五分钟“补写取消整个请求”计时器。

## 阶段报告接口

SSE/JSON 的阶段报告合约为 `deliveryAvailable=true`、`deliveryKind=partial_report`、`runTerminated=true`、非空 `deliveryText`。完整评估字段继续为 false。

`runTerminated` 描述执行循环已停止，不表示所有工具都成功。因取消/错误/预算结束而无法等到工具终态时，报告须保留 pending 记录和未完成警告；前端可以显示阶段报告，但不得把这些工具标为完成。仍等待审批的交接不伪装终止。

报告读取当前会话与匹配项目的任务信息、按工具/状态汇总、可核对执行 ID、已有漏洞登记原状态、覆盖进度和缺口。工具次数不是验证次数，候选数量不是漏洞数量，登记发现不是重新验证。数据读取失败时说明未知，不把未知写成零或静默不交付。

`candidateReport` 单独携带模型候选原文（也可由历史 `finalization_check.finalText` 恢复），前端用纯文本折叠展示，明确未经完整检查。正文仅使用 `deliveryText`；候选和晚到事件不得覆盖已经保存的报告。

## 持久化结果入库

原始结果快照、不可变执行绑定与 pending 任务在同一数据库事务中保存。内存仅保留唤醒信号；两个处理线程从数据库原子领取任务，领取令牌、租约和尝试次数防止并发重复完成或过期线程覆盖新状态。失败最多五次带退避重试，原件与错误保留；进程重启继续领取待处理任务。

同一原件重试时须匹配绑定及字节/哈希，拒绝变化、符号链接和跨会话/项目绑定。离线恢复只处理明确选定的执行 ID，读取已有原件重新解析，不重新执行扫描或其他工具，不直接把失败改成成功。旧任务没有历史权限快照时，保守不新增资产/候选投影，不提升权限。

## 部署与验收

部署需重新编译后端并同步前端；有活动任务时先安排维护窗口，磁盘代码更新不会改变旧进程。已停止任务不会自动重跑扫描。

重点回归包括：提交报告后仍等待后台工具；空 exit 不能丢失后台状态；大型候选集转分类验证；错误/取消/数据库不可用仍有明确阶段报告；持久队列重启、重试、租约、幂等及权限隔离；前端候选隔离和未完成报告显示。
