# 本地工具工作区隔离

## 执行边界

Eino 单任务、Deep、Supervisor、Plan-Execute 的模型文件工具使用服务端确定的工作区。相对路径以该工作区为基准，不再继承应用根目录。当前项目工作区允许读写，当前项目的结果暂存目录及技能目录允许只读；平台源码、配置、其他项目及历史共享 `skills/.eino` 状态不可访问。计划文件存放在当前工作区的 `.eino/plantask` 中。

文件读写、列举及检索使用 `os.Root`，拒绝路径遍历和符号链接。修改路径提示词不是访问授权；传入新的 `workdir` 也不能扩大边界。

Linux 的 `exec`、原生 `execute` 和配置型命令工具统一通过 bubblewrap 启动，使用独立的文件系统、PID、IPC 和 UTS 命名空间，移除 Linux capabilities，并以真实非 root 宿主身份运行，再创建用户命名空间，避免把宿主 root 映射成非零 UID 后仍绕过进程数限制。root 服务会先将当前工作区和当前项目结果目录的所有者设为执行身份（UID/GID 65534），并仅为其补充祖先目录的穿越 ACL；不改动平台文件、技能文件或工具安装目录的所有者。宿主 `/root`、应用根目录、配置和宿主 `/proc` 不挂载，服务环境中的模型/数据库密钥不继承。FOFA 等服务端凭据仅注入对应具名工具。

普通输出默认位于工作区；`HOME`、临时目录、缓存和工具私有状态也在工作区内。平台托管的原件仍使用按项目和 execution ID 隔离的结果目录。当前 execution 只能写自己的原件目录，其他历史结果只读。

## Linux 部署

安装 `bubblewrap`（root 服务另需 `acl`）并确保 user/mount/PID namespace 可用。缺少隔离组件或命名空间不可用时，调用明确失败，不会退回裸执行。其他操作系统目前没有等价命令沙箱，受约束命令应明确拒绝，不能宣称已隔离。

`security.local_sandbox_runtime_paths` 可以配置经过管理员审核的只读工具安装目录；禁止填整个 `/`、`/opt`、应用根目录、用户目录或数据目录。脚本若原来位于平台仓库，应将其所需的工具运行文件复制到独立安装目录，不要为方便而挂载整个源码目录。Python 虚拟环境可单独只读挂载。

`security.local_sandbox_writable_runtime_paths` 只允许前述运行目录的子目录。例如 OneForAll 的 `results`，在隔离进程内会映射到当前工作区 `.tool-state/<路径哈希>`；宿主安装目录的历史结果既不读取也不覆盖。此配置不是宿主目录写权限。

要求 root/raw socket 的扫描方式可能受 capabilities 限制。优先使用工具原有的非特权模式；不应为了兼容而恢复任意宿主 root 权限。末尾 `&` 或原生后台模式拒绝脱管执行，长任务使用平台的 `execution_id`、`get_tool_execution` 和 `wait_tool_execution` 管理。

网络仍沿用宿主网络以保持工具连接能力；这不是完整的网络隔离方案。外部 HTTP/SSE MCP 的实际执行环境及共享 stdio MCP 服务，需要单独实施服务端隔离，不能据此宣称它们已获得逐项目文件系统隔离。管理终端也不属于模型工具沙箱。

## 事故处置与验证

已经进入模型上下文的配置密钥应在相应提供商处撤销/轮换。隐藏文件或删除本地日志不能撤回历史模型请求。暂停受影响任务，先保留受保护的原始备份，再清理用于续跑的含密钥上下文；旧根目录产物只在归属明确时迁移，不能按文件名猜测归属或删除未知文件。

离线回归包括：分段读取伪造配置、绝对路径与 `..`、符号链接、跨项目和并发策略、只读技能和当前结果读取、默认目录、Shell/Python 越界、环境密钥、具名工具、私有运行目录、缺少 bubblewrap，以及 MCP 协议入口的执行 ID 绑定。测试使用本地哨兵文件，不访问业务目标。
