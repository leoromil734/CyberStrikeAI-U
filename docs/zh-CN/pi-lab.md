# PI 实验室：平台正式模式

## 目标与模式

PI 继续负责模型推理、工具循环和多 Agent 派发；正式模式将操作交给 CyberStrikeAI 现有业务层执行，复用本项目的 **“渗透测试”角色、Skill、工具、项目、监控和证据治理**。它不是 iframe，也不再只做 HEAD/GET 响应头演示。

页面默认新建 `platform` 正式任务。`probe` 保留旧版受限 HTTP 诊断，旧历史及省略 `mode` 的旧 API 请求仍按诊断处理，不自动升级权限。

参考 `others/StrikeAgent_AtkBrain-Flash` 的职责划分：运行时负责会话，应用层负责编排、工具和图。没有复制其 AGPL 源码、提示词、Skill 或前端资源。实际依赖为同源 MIT 许可的 `@earendil-works/pi-coding-agent@1.0.4`，独立锁定 npm 依赖。

## 正式模式能做什么

- 使用运行时配置中的 `roles/渗透测试.yaml` 对应角色，而不是在 Node 内复制一份提示词；角色未启用、未配置或基础技能不可用时明确拒绝启动。
- 注入平台共享的授权、执行、证据、覆盖和报告契约。协调者和工作者采用各自的生命周期指令，工作者只完成交接目标、不递归派发。
- 按项目已有技能目录生成 `name/description` 索引，通过 `load_skill`、`read_skill_file` 渐进读取正文和引用。先加载 `pentest-agent-os`，后续领域、深度和验证 Skill 遵守角色的路由规则。
- 使用角色允许且已注册的扫描器、`exec`、Python 执行、事实、候选、漏洞记录、知识及结果读取工具。调用走现有 MCP 服务及授权器，不直接绕过平台执行器。
- 在已有项目内创建绑定属主的新对话，登记原任务管理器和评估记录；工具执行保留真实 `execution_id`，结果继续经过原监控、结果处理及证据入库流程。
- PI 页面显示真实父子 Agent、工具关联图、事件、报告、已加载技能及执行记录，并可跳转到关联项目、对话、漏洞和工具监控。
- 对长会话使用 PI SDK 支持的自动上下文压缩；摘要请求也计入所有会话共享的模型预算，不产生不受控的额外调用。
- 在模型返回报告后调用现有平台交付门禁。缺少实际执行、后台任务未结束、覆盖账本未闭合或报告不满足要求时，只交阶段报告，不能仅因模型写了“完成”就显示完整完成。

这是可调用平台完整工具链的正式接入模式，不代表已对所有模型、扫描器或真实目标完成生产验收，也不保证自动发现所有漏洞。

## 角色和工具复用规则

默认角色固定为“渗透测试”，实际读取服务器已加载的角色配置，尊重 `enabled`。不能通过前端请求直接传入系统提示、工具定义、工作目录或执行身份。

工具目录由角色白名单与已注册工具取交集，再经过权限过滤；补充现有流程必需的受控邮箱、候选管理、执行等待/取消和证据读取工具。缺少或未安装的工具会显示不可用或执行失败，不会伪造工具结果，也不会自动扩大为所有平台工具。

外部 MCP 工具需要在角色 `tools` 中明确列出 `服务器名::工具名`，并满足现有外部 MCP 权限要求。桥接名称映射为 `服务器名__工具名`。不会把旧的 MCP 服务器名单隐式当作全工具授权，也不会加载用户 PI 的全局插件、技能、MCP 配置或凭据。

PI 自带的 `bash/read/edit/write` 保持关闭；正式文件和命令能力由平台桥接提供：

- `load_skill({name})`：读取已登记 Skill 的正文。
- `read_skill_file({name,path})`：读取该 Skill 包内的相对路径引用。
- `read_file({path,offset?,limit?})`：读取当前项目工作目录或受控只读技能/证据目录；`offset/limit` 按字节计算。
- `write_file({path,content})`：仅写当前工作目录中的普通文件。
- `list_files({path?})`：有界列举目录直接子项。
- `exec` 等操作沿用平台原执行器、工具预算、凭据处理及本机执行隔离。

文件访问使用服务端工作目录策略及 `os.Root`，拒绝路径穿越、符号链接和硬链接别名，不向模型开放平台源码、配置或其它项目目录。

## 项目、权限与范围

正式任务必须选择可访问的已有项目，并明确填写授权范围和勾选确认。输入允许 URL 路径、内网地址、CIDR 和授权范围描述，不再套用诊断模式的“公网 origin + 明示 URL”限制。

项目范围与本次授权范围取交集；冲突、不明确和缺失授权应按共享任务契约停止相应主动动作。**范围文字是任务约束，不是网络层强隔离**；任意命令的出站限制仍取决于平台既有执行环境和网络策略。

启动正式模式至少需要：

- `agent:execute`、`agent:local-execute`；
- `chat:write`；
- 对该项目的 `project:read` 和 `project:write`。

具体工具仍检查自身的漏洞、监控、知识、资产等权限。每次工具调用重新验证会话及项目访问，并由服务端绑定项目、对话、消息和属主。模型不能把平台结果写到另一个项目或会话。

PI 记录仍按创建者隔离；正式模式读取历史还检查当前项目访问权限，失去项目权限后不能从 PI 历史继续读取项目结果。取消本人任务不要求重新获得该项目结果的读取权限，但返回值会隐去已撤销权限的数据。

## 桥接和密钥

每个正式运行创建一个仅监听 `127.0.0.1` 临时端口的工具桥，只允许固定路径 `POST /tools/call`。随机运行凭据与角色快照通过子进程 stdin 传递，不放到 URL、命令行、前端或 `run.json`。

Node 仅持有本次工具桥凭据，不持有平台登录会话。调用方不能选择 Go 执行身份；后台执行继续使用经过验证的用户、项目、对话和工作目录上下文。桥禁止浏览器 Origin、跨主机和重定向，校验工具白名单，并限制请求大小、并发和总调用数。

模型 Key 沿用所选 AI 通道的服务端快照。支持 OpenAI 兼容 Chat Completions 和 Claude Messages；启动后的任务不会因为修改通道配置而切换模型。

## 预算和收尾

正式模式默认：3 个并行工作者、最多 12 个子 Agent、3600 秒、120 轮模型调用、600 次自定义工具调用。协调者和全部工作者共享预算，自动摘要也计入模型轮次。

界面可调整至：并发 8、子 Agent 32、21600 秒、模型 500 轮、工具 2000 次。它们不会覆盖或放宽平台执行器已有的全局限额。

同一后端默认同时运行 1 个 PI 任务；可通过 `CYBERSTRIKE_PI_MAX_RUNS` 调整为 1–4 个。该配置只控制独立 PI 任务数量，项目内的工作者并发另算。

- 工具异步等待不会被当作任务已经完成。模型使用真实执行 ID 查询、等待或取消后台任务。
- 取消、超时和收尾会取消本次登记的未完成 MCP 执行，不能仅杀 Node 而遗留扫描，也不取消其它对话的工具。
- 任务结束后将报告和交付状态保存到原对话、任务及评估记录。未通过门禁保留 `partial/failed/cancelled` 等状态，不会升级为完整完成。
- 服务异常退出后只恢复中断状态和关联元数据，不自动重放真实操作。已有执行证据保留；需要继续时按原配置新建任务。
- 页面“按此配置新建”只复制字段，不自动提交或勾选授权。

## 可视化与事实的区别

`record_surface`、`record_finding` 是 PI 内的图笔记，不构成正式漏洞确认。正式模式中的 `record_vulnerability` 必须经过平台原来的验证与入库条件。最终结论以原项目、漏洞模块和证据记录为准。

模型会话结束、图中节点成功和漏洞已验证是不同状态。PI 页面的“候选/观察”不替代原漏洞库；工具执行 ID 用于核对实际原件及归属。

## 诊断模式兼容

`probe` 保留原有隔离记录与工具：`inspect_http`、`record_surface`、`record_finding`、`delegate_agents`。仅允许授权公网来源及原需求明示 URL 的 GET/HEAD，不跟随跳转，不向模型返回原始响应正文，仅观察响应头、字节数和 SHA-256。

旧数据和旧请求不会因为升级正式模式而获得 Shell、项目或平台工具能力。旧诊断的预算上限、属主隔离和测试仍保留。

## 安装与启用

需要 Node.js **22.19+**（建议 24 LTS）。在实际运行后端的主机、项目根目录执行：

```sh
npm --prefix runtimes/pi-lab ci --ignore-scripts --no-fund --no-audit
node runtimes/pi-lab/runner.mjs --check
```

部署正式模式需要同时更新 Go 后端、`web/` 和 `runtimes/pi-lab/`，不能仅替换 Node 文件。已有环境若已启用 PI，保持原开关即可；首次启用为后端进程设置：

```sh
CYBERSTRIKE_PI_ENABLED=true
```

其它环境变量：

- `CYBERSTRIKE_PI_NODE`：Node 可执行文件，默认 `node`。
- `CYBERSTRIKE_PI_RUNNER`：runner 绝对路径，默认从启动工作目录解析 `runtimes/pi-lab/runner.mjs`。
- `CYBERSTRIKE_PI_DATA_DIR`：独立记录目录，默认 `data/pi-lab`。
- `CYBERSTRIKE_PI_MAX_RUNS`：并行 PI 任务数，默认 1，最多 4。

为同一个数据目录只运行一个后端进程。当前文件型 PI 历史不是多副本共享队列；需要多节点高可用时应另行设计共享存储和任务租约。

启用不会自动请求模型或测试目标。首次正式任务应在自建或明确授权环境验收，确认项目范围、角色、Skill、工具依赖和权限后再提交。真实模型调用可能收费。

## 接口与记录

- `GET /api/pi-lab/status`：运行时就绪、两种模式和预算，不探测模型连通性。
- `GET /api/pi-lab/profile`：当前平台角色、Skill/工具索引和正式预算；缺权限或配置时明确说明，不降级为诊断。
- `GET /api/pi-lab/runs`：本人且当前仍有权读取的记录索引。
- `POST /api/pi-lab/runs`：异步创建；正式模式传 `mode:"platform"`、`project_id`、`role:"渗透测试"` 以及范围/授权/预算。
- `GET /api/pi-lab/runs/:id`：详情、图、报告、项目/对话/技能/执行 ID。
- `GET /api/pi-lab/runs/:id/events?after=0`：每页最多 100 条增量事件。
- `POST /api/pi-lab/runs/:id/cancel`：取消本人运行。

PI 展示记录保存于 `data/pi-lab/runs/<uuid>/run.json` 和 `events.ndjson`；正式业务数据存入原项目和对话体系。记录可能包含敏感业务证据，应按项目数据保管。

默认最多 1000 条 PI 历史，索引最多显示最近 100 条本人记录；到上限后拒绝新建，由管理员离线归档，不自动删证据。正式模式每次最多 12000 条事件、64 MiB 事件日志及 8 MiB 状态快照；诊断保留旧限制。大工具结果留在既有证据存储，通过结果读取工具分段获取，避免在 PI 事件中重复复制。

## 验证方法

```sh
npm --prefix runtimes/pi-lab test
node --test web/static/js/pi-lab.test.cjs
go test ./internal/pilab
go test ./internal/handler ./internal/security ./internal/app -run 'TestPILab|TestEveryProtectedRouteHasCatalogPermission' -count=1
go build ./...
```

测试使用本机模拟模型与工具，不访问真实目标，包括：真实 PI SDK 经 Go 工具桥执行 Skill、工作区文件和 MCP 工具，执行 ID 持久化，已有平台门禁阻止伪造完成；还直接加载本仓库渗透测试角色、Skill 目录和工具 YAML，检查生成目录能被当前 PI/TypeBox 编译。

补充验证覆盖工具白名单、项目权限变更、跨项目标识、工作目录和链接边界、后台执行取消、共享预算、自动压缩、密钥不落盘，以及页面身份切换和旧记录兼容。SQLite 测试需有效 CGO 编译器；Windows 默认 GCC 不兼容时可只在测试进程临时使用 Zig cc，不修改全局工具链。

### 已保留的 HTTP 清理修复

早期诊断试验曾在 HEAD 或重定向清理未消费响应体时触发 Undici `UND_ERR_ABORTED`，导致子进程退出。已在销毁前处理预期的流错误并实现幂等关闭；真实 HTTP/SDK 回归覆盖正常请求、跳转、重复关闭、超时和响应大小限制。平台桥也保留同类响应流保护，不通过放宽范围或吞掉正常读取错误规避问题。
