# 模型通道管理与漏洞来源统计

## 使用方式

1. 在「设置 → 基本设置 → AI 通道配置」中选择通道。连接、密钥、型号、Token 上限、推理及视觉配置会同步切换，切换本身不会保存配置或调用上游模型。
2. 批量导入时，先填写服务地址和密钥，展开「从当前地址和密钥批量导入模型」，获取列表、搜索并勾选所需型号，设置命名前缀，再导入。每个型号生成一个独立通道，命名为前缀与模型名称的直接拼接；需要分隔符时将其写入前缀。
3. 同一协议、地址、密钥和型号的重复项会跳过。名称归一化发生冲突时，内部通道 ID 自动增加数字后缀。服务没有模型列表接口时，可按行粘贴型号列表。
4. 导入结果首先成为配置草稿，点击「保存更改」后持久化并应用。保存当前通道不会自动将其改为默认通道。
5. 点击「测试全部已保存模型」或「测试选中」。没有勾选时，「测试选中」仅测试当前通道。测试会产生少量上游 API 费用；未保存的草稿不会作为测试配置。
6. 测试记录展示状态、首 token 时间、总耗时、测试时间和错误信息。刷新页面仍会显示结果，配置变化会标记为需重测。配置完整但未经测试的模型显示「未测试」，而不是「可用」。
7. 「漏洞管理 → 通道与模型发现统计」支持通道 + 型号、仅型号、仅通道三种分类，展示数量、严重度、处理状态和漏洞类型。点击「查看漏洞」可下钻到列表，筛选条件同样用于导出。

## 视觉配置兼容性

- `ai.channels.<id>.vision` 缺省或为 `null` 时，沿用旧版全局 `vision` 配置。
- 取消「沿用旧版全局视觉配置」后，可以为当前通道单独设置视觉型号、地址、密钥和预处理参数。地址、密钥和协议留空时复用当前运行通道，而不是另一个默认通道。
- 显式 `enabled: false` 会关闭该通道的视觉调用，不能回退到其他通道。
- 单代理、多代理、工作流及批量任务都使用本次运行的配置快照；不同并发任务的视觉配置互相隔离。

## 数据语义

- 新漏洞的 `ai_channel_id`、`ai_channel_name`、`ai_model` 由服务端从当前会话的运行记录自动写入。客户端或工具参数不能覆盖这些字段。
- 修改漏洞、切换后续会话模型、重命名通道或删除会话，不会修改已有漏洞的来源快照。
- 既有漏洞没有可靠的发现时来源，因此保留为「未记录」，不会根据当前默认配置补填。部分来源缺失也可以独立筛选。
- 统计采用数据库聚合，并复用漏洞列表的项目、会话、严重度、状态和访问权限限制。数量是正式漏洞记录数，不代表模型准确率。
- 首 token 时间为流式请求开始到首个非空文本片段的时间；不把响应头、角色字段或纯思考片段当作文本 token。未取得文本时该指标为空。
- 每个通道保存最近一次测试记录。上游返回内容与 API Key 不写入测试结果；仅在数据库保存不可逆配置指纹用于判断结果是否过期。

## 新增接口

- `GET /api/config/ai-channel-probes`：读取测试记录，需要配置读取权限。
- `POST /api/config/ai-channels/:id/test`：测试已保存通道并保存结果，需要配置写入权限；服务端最多并发三个测试，每次最多 45 秒。
- `GET /api/vulnerabilities/model-stats`：按 `group_by=channel_model|model|channel` 汇总；需要漏洞读取权限，且只统计可访问记录。
- 漏洞列表、统计及导出新增 `ai_channel_id`、`ai_model`、`unattributed=true`、`ai_channel_missing=true`、`ai_model_missing=true` 筛选参数。

数据库字段和测试记录表在启动时自动幂等迁移。上线前仍建议备份配置与数据库，并重新构建、重启服务后刷新浏览器。本次验证使用本地模拟上游和临时 SQLite 数据库，没有调用真实模型渠道或改动生产数据；PostgreSQL 运行环境需另行验收。
