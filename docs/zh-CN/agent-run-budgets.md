# 任务续跑与事实补写保护

## 本次请求的总时限

Eino 单角色、多角色的流式与非流式入口分别创建请求级绝对截止时间。自动覆盖补写、空回复重试、中断并继续使用同一个请求根上下文，不再各自领取新的 600 分钟预算。停止任务会取消整次请求；旧执行段的普通清理不会误取消后续执行段。新的明确用户请求会创建新的预算。

## 事实写入预算

`agent.max_fact_writes_per_run` 控制同一请求内通过校验的 `upsert_project_fact` 变更次数，默认 1024（未配置或不大于 0 时使用默认值）。字段校验失败和内容完全相同的重试不占用额度。额度用完只拒绝后续事实写入，不取消正在进行的工具验证、原件保存、漏洞记录或报告整理。

预算不会删除已有事实，也不把库存自动改成完成。人工管理接口等非模型调用不受这个模型运行预算约束。预算在本次请求第一次事实调用时固定，途中调高配置不会让正在运行的请求重新获得次数。

## 有界覆盖补写

- 覆盖检查仍保留原始库存、来源与缺口。未处置的独立候选工作组超过 100 时，停止自动逐 URL 补写，明确返回未完成数量和样例，而不是要求模型生成上万条 N/A。
- 原始 URL/资源明细应留在库存和结果工件。项目事实用于新的可复用结论和有证据的必要处置；未知、历史候选不等于当前已验证业务入口。
- fact 数量增加、台账映射变多、格式修正或错误清单变短，都不算测试进展，也不能重置续跑计数。连续两段没有新增可核查执行证据时，停止逐条补写，转为实际漏洞验证。连续八段仍没有新的执行证据才停止自动推进；有新扫描或验证证据时继续，直到 64 段工作上限。
- 实际工作续跑和报告收尾分别计数。仍有可执行覆盖缺口时，简短或未提交的候选不会提前耗尽报告额度。实际工作最多 64 段，报告收尾最多 4 段；用户取消、请求截止和工具自身时限仍然有效。
- 批量子任务与交互任务共用 600 分钟绝对时限，自动续跑不会重新领取 6 小时。
- 阶段报告保存在任务结果和助手消息。任务错误与队列 `lastRunError` 只保留状态、原因和覆盖计数，不再拼接整份报告。

这些保护表示“未完成并保留缺口”，不是降低库存数量或放宽到“全部安全”。海量历史 URL 需要按授权范围、当前性、业务功能和可核实证据进行分类；当前实现不会自动推断整组风险不适用，也不会批量伪造否定记录。

## 原有任务与部署

现有原件、库存和事实不自动删除或改写。旧的纯说明文字、N/A-only 等记录不能凭数量通过独立库存处置检查；需复核其证据。部署后，已经停止的任务保持停止，不自动恢复扫描。

后端保护需要重启服务加载。若还有其他任务正在执行，应先选择维护窗口；只更新磁盘源码或构建新程序不会改变现有进程的运行规则。
