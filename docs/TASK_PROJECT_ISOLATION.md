# 批量任务项目隔离与目标历史

## 创建与项目绑定

新建任务合集时可勾选“每个任务创建独立项目”。HTTP 参数为 `independentProjects: true`，批量任务 MCP 参数为 `independent_projects: true`；需要启用项目功能及 `project:write` 权限。默认 false，保留旧 API 和已有队列的共享项目行为。

独立模式不能同时指定共享 `projectId/project_id`。每条任务获得不同项目，即使两条输入的目标相同也不共享事实。项目名由首个可提取的目标加随机 ID 组成，无明确域名时用 `task-随机ID`；这个名字只用于展示，不将归一化域名转换成更宽的授权范围。

项目、任务、合集和目标提交登记在创建事务中保存；任一写入失败会回滚，避免孤立项目或只有历史没有任务。队列和新项目归发起用户所有。

重启、普通重跑与 Cron 轮次保留每条任务的项目标识。追加任务创建新项目；修改已经执行过的独立任务，或修改其目标集合时，未来执行改用新项目，原会话和事实仍留在原项目。独立项目丢失或不可访问时停止该任务，禁止回退到共享或默认项目。

创建选项只作用于新合集，不自动迁移旧合集的会话、事实、漏洞或关系边。删除任务/合集也不自动删除已有项目证据。

## 历史目标与重复提醒

目标记录分为两类：

- 已提交：创建、追加、编辑任务时，使用完整原始任务文本提取并幂等登记；未执行任务也能被重复检查命中。
- 已运行：任务/会话开始执行时另行登记，同一个目标和会话只计一次，继续追问不会增加次数。

未执行的提交记录不能显示成一次运行。重复检查允许同一用户跨项目发现重复，不以项目隔离为由清空个人历史；权限查询防止泄露其他用户的私人记录。

输入预览采用防抖，真正创建前再次查询，避免其他页面刚登记目标而缓存仍显示“无重复”。短合法域名也进行检查；检查服务失败时明确提醒，而不静默当成没有历史。

启动补漏读取已有任务的完整 `message` 和原始用户输入，不从助手输出、角色模板、扫描结果或截断标题推断目标。无原始输入时才兼容历史标题。回填可重复执行，不重复增加提交数或运行数。

目标历史与资产库是两套记录。登记任务目标不代表该目标已探活、完成测试或被导入资产库。

## 工具流程保护

工具入库时对非法 UTF-8 和 NUL 做可见 `\\xhh` 转义，合法文本不变；不修改原始运行缓冲、字节计数或工具真实终态。旧 orphaned 记录不会仅因编码修复被猜测成成功。

原生文件读取在同一执行上下文中连续返回同一个片段的相同结果 3 次后，再次确认结果未变化时改回简短的无进展提示，不重复重放整段正文。它不是全局缓存，仍实际读取以发现文件变化；不同分页、文件或专项上下文独立，内容或版本变化后重新允许返回。此提示不能替代覆盖证据或自动宣称完成。

## 暂停与继续

队列暂停把中断的子任务记为 `paused`，保留会话、证据及未完成步骤；显式继续复用原会话和轨迹，不将暂停当成永久取消，也不重新全量侦察。恢复前要核对未结束工具与已发生的副作用。真正 cancelled 的任务不会自动领取；只有 cancelled/completed/failed 的暂停合集不能空跑后宣称完成，需要显式单项重跑或新增任务。

暂停收尾期间保留执行器所有权，禁止强制清除执行器后另开重复 worker，禁止编辑仍在收尾的任务。晚到的取消函数登记会立即响应暂停，避免暂停后新工具继续启动。
